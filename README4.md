# Домашнее задание к занятию "`Репликация и масштабирование. Часть 2`" - `Первушин Дмитрий`

### Задание 1

Опишите основные преимущества использования масштабирования методами:
- master-сервер и пассивный репликационный slave-сервер;
- master-сервер и несколько slave-серверов;
Дайте ответ в свободной форме.

### Решение 1

1. Архитектура с активным master и пассивным slave-сервером
Ключевые преимущества:
- Высокая доступность. При сбое master-сервера происходит автоматическое переключение на slave, что минимизирует время простоя системы.
- Резервное копирование. Пассивный slave постоянно содержит актуальную копию данных, что упрощает процесс резервного копирования и восстановления.
- Снижение нагрузки. Возможность переноса операций чтения на slave-сервер, разгрузка master от запросов SELECT.
- Простота реализации. Минимальное количество компонентов системы упрощает настройку и обслуживание.
- Автоматическая синхронизация. Репликация данных происходит в фоновом режиме без дополнительного вмешательства.
- Экономическая эффективность. Требуется минимальное количество серверов при сохранении отказоустойчивости.

2. Архитектура с master и несколькими slave-серверами
Ключевые преимущества:
- Масштабируемость чтения. Распределение нагрузки между несколькими slave-серверами позволяет обрабатывать значительно больше запросов на чтение.
- Гибкое распределение ресурсов. Каждый slave может быть настроен под конкретные задачи: аналитика, отчеты, резервное копирование.
- Повышенная отказоустойчивость. Даже при выходе из строя одного slave-сервера система продолжает работать в полном объеме.
- Географическое распределение. Возможность размещения slave-серверов в разных регионах для локального доступа к данным.
- Оптимизация производительности. Балансировка нагрузки между slave-серверами обеспечивает стабильную работу системы.
- Расширяемость. Простота добавления новых slave-серверов при росте нагрузки.

### Задание 2

Разработайте план для выполнения горизонтального и вертикального шардинга базы данных. База данных состоит из трёх таблиц:

пользователи,
книги,
магазины (столбцы произвольно).
Опишите принципы построения системы и их разграничение или разбивку между базами данных.

Пришлите блоксхему, где и что будет располагаться. Опишите, в каких режимах будут работать сервера.

### Решение 2

### 1. Горизонтальный шардинг

Можно использовать различные варианты, в зависимости от размера магазина. Например:

Шардинг таблицы Пользователи:
- По географическому признаку (если пользователи в разных городах/странах)
- По ID пользователя (диделим по диапазонам, если много пользователей)

Шардинг таблицы Книги:
- По жанрам
- По издательству

Шардинг таблицы Магазины:
- По географическому признаку (если магазины в разных городах/странах)
- По размеру магазина (например, самостоятельный магазин или отдел в ТЦ)

### 2. Вертикальный шардинг

Можно применить вариант шардирования по бизнес-логике процессов. Например:

1. Пользовательские операции
- Таблица Пользователи (все операции)
- Профиль пользователя (любимые авторы, жанры, магазины)
- Аутентификация и авторизация (логин, пароль)

2. Операции с книгами
- Таблица Книги (все операции)
- Контент (автор, жанр)
- Метаданные (аннотация, издательство, год выхода)

3. Складские операции
- Таблица Магазины (все операции)
- Складской учет (наличие и количество книг в магазинах)
