### Задание 1. Резервное копирование

### Кейс

Финансовая компания решила увеличить надёжность работы баз данных и их резервного копирования.  
Необходимо описать, какие варианты резервного копирования подходят в случаях:  
1.1. Необходимо восстанавливать данные в полном объёме за предыдущий день.  
1.2. Необходимо восстанавливать данные за час до предполагаемой поломки.  
1.3.* Возможен ли кейс, когда при поломке базы происходило моментальное переключение на работающую или починенную базу данных.  
Приведите ответ в свободной форме.

### Решение 1

### Варианты резервного копирования для финансовой компании

1.1. Восстановление данных в полном объеме за предыдущий день  
Рекомендуемые методы:  
- Полное резервное копирование  
- Инкрементное копирование

Схема реализации:
- Ежедневное полное копирование в ночное время
- Хранение копий за последнюю неделю локально
- Хранение архивных копий за месяц на удаленном сервере
- Регулярная проверка целостности резервных копий
- Регулярное проведение тестового восстановлени из резервной копии

1.2. Восстановление данных за час до поломки  
Рекомендуемые методы:  
- Дифференциальное копирование
- Непрерывное резервное копирование

Схема реализации:
- Полное копирование ежедневно
- Дифференциальные копии каждый час
- Хранение последних 24 часов на быстром хранилище SSD

1.3. Моментальное переключение баз данных
Возможные решения:

- Репликация баз данных
- Кластеризация БД
- Snapshot-технологии

### Задание 2. PostgreSQL
2.1. С помощью официальной документации приведите пример команды резервирования данных и восстановления БД (pgdump/pgrestore).  
2.1.* Возможно ли автоматизировать этот процесс? Если да, то как?  
Приведите ответ в свободной форме.

### Решение 2

2.1 Примеры команд резервного копирования и восстановления

Создание резервной копии (pg_dump):
```
pg_dump -U username -W -F c -f "/path_to_backup/backup_file.dump" dbname

```

Восстановление базы данных (pg_restore):
```
pg_restore -U username -d dbname -W -F c -C "/path_to_backup/backup_file.dump"

```

2.2. Пример автоматизации процесса

Можно добавить задачу в cron
```
0 0 * * * /usr/bin/pg_dump -U username -F c -f "/path_to_backup/backup_$(date +%Y-%m-%d).dump" dbname

```
Также существуют специализированные утилиты - Barman.

### Решение 3

3.1. Пример команды инкрементного резервного копирования MySQL

Для выполнения инкрементного бэкапа в MySQL можно использовать бинарные логи (binary logs).
```
mysqlbinlog \
    --start-datetime="2023-03-01 00:00:00" \
    --stop-datetime="2023-03-02 00:00:00" \
    --to-last-log \
    --result-file="/path_to_backup/incremental_backup.sql" \
    binlog.000001 binlog.000002 ...

```

3.1.* Преимущества репликации перед обычным резервным копированием

Репликация имеет следующие ключевые преимущества:
1. Производительность системы:  
- Снижение нагрузки на основной сервер
- Возможность выполнения операций чтения с реплик
- Копирование данных без влияния на производительность основного сервера

2. Высокая доступность:  

Быстрое переключение при отказе основного сервера

Обеспечение непрерывной работы системы

Минимизация времени простоя

3. Масштабируемость:  

Распределение нагрузки между серверами

Добавление новых реплик для увеличения производительности чтения

Географическое распределение данных

4. Функциональные возможности:  

Восстановление на определенный момент времени

Выполнение аналитических запросов без влияния на основную систему

Создание тестовых сред без воздействия на продуктивную базу

5. Распределение данных:  

Локальное размещение данных для пользователей

Повышение устойчивости к региональным сбоям

Оптимизация доступа к данным

6. Безопасность:  

Возможность разграничения доступа к репликам

Создание изолированных сред для разных целей

Защита основной базы данных от тяжелых запросов
